# AI Instruction — Go Echo Boilerplate

This document provides context for AI agents to understand the structure and conventions of this codebase when generating or modifying code.

---

## Project Identity

- **Module name**: `go-serviceboilerplate` (used in all import paths)
- **Language**: Go 1.26+
- **HTTP framework**: Echo v4
- **ORM**: GORM with PostgreSQL
- **Document database**: MongoDB (`go.mongodb.org/mongo-driver/v2`)
- **Cache**: Redis (`github.com/redis/go-redis/v9`)
- **Message broker**: STOMP (`github.com/go-stomp/stomp/v3`) — ActiveMQ, RabbitMQ STOMP plugin, Artemis
- **Object storage**: any S3-compatible storage — AWS S3, Cloudflare R2, MinIO (`aws-sdk-go-v2/service/s3`)
- **LLM**: LangChainGo (`github.com/tmc/langchaingo`) with Ollama, Gemini, or OpenAI
- **Auth**: JWT (golang-jwt/jwt v5) + bcrypt password hashing
- **Logging**: `log/slog` JSON logger

## Architecture

This project follows **Clean Architecture** with four layers. Dependencies flow inward — outer layers depend on inner, never the reverse.

```
interfaces → applications → infrastructures → commons
```

| Layer | Location | Responsibility |
|---|---|---|
| Interface | `interfaces/http/` | HTTP handlers, routes, middlewares, validator |
| Application | `applications/usecases/` | Business logic, orchestrates repositories and security |
| Infrastructure | `infrastructures/` | Config loading, DB/cache/storage/LLM clients, repositories, security |
| Commons | `commons/` | Shared models, constants, utilities |

---

## General Conventions

- **Constants and shared vars live in `commons/models/constant.go`**, not inside infrastructure or handler packages. This includes shared sentinel errors such as `models.ErrCacheMiss`.
- **Tunable values come from env vars, not constants.** Timeouts, TTLs, pool sizes, expirations and the like are fields on a `*Config` struct in `commons/models/configs.go`, loaded in `infrastructures/configurations/env.go` with a default. `GetEnvInt` returns the default only when the variable is missing or empty — an explicit `0` is kept as `0` and negative values stop startup — so a zero value must have a defined, safe meaning (library default, "disabled" or "no limit") documented on the field.
- **Every config field has a comment** stating what it does and its env var (with unit and default). Keep this up to date when adding fields.
- **Logging uses slog key/value pairs**: `configs.Logger.Info("Message", "key", value)`. Never pass printf-style format strings or a bare `err` — use `"error", err`.
- **Infrastructure constructors fail fast**: on a bad config or failed connection, call `configs.Logger.Fatal(...)` at startup instead of returning a broken client.
- **Pass `ctx context.Context` as the first parameter** of every use case, repository and I/O method — see "Context" below.
- **File and folder names with more than one word use `_`** (e.g. `message_broker.go`, `request_context/`). Go package names follow the folder name.
- **Unexpected errors never reach the client.** `utils.ErrorResponse` returns non-`*utils.Exceptions` errors as a generic `500 Internal Server Error` with an error `id`, and logs the real error with the same `error_id` and the `request_id`. Return `utils.New…Error` for anything the client should see.
- **Compare secrets in constant time** (`crypto/subtle`), never with `==`.
- **Wrap returned errors with context** using `fmt.Errorf("<component> <operation> %q: %w", key, err)` so callers can still use `errors.Is`/`errors.As`.

## Layer Conventions

### `commons/models/`
- Pure data structs, constants and shared errors used across all layers.
- No business logic. Dependencies are limited to the stdlib and type-only imports (JWT claims, Echo `middleware.CORSConfig`).
- Key files:
  - `configs.go` — `ENVConfig` (root) with `ApplicationConfig`, `PostgresConfig`, `MongoConfig`, `RedisConfig`, `StompConfig`, `S3Config`, `LocalStorageConfig`, `LLMConfig`
  - `authentications.go` — `AccessTokenClaims`, `RefreshTokenClaims`, auth request/response types
  - `queries.go` — `Queries`, `FilterQueries`, `QueriesOptions`, `BaseQueriesRequest`
  - `constant.go` — custom HTTP headers (`X-Client-Id`, etc.), filter operators, `LLMProvider` values, `AgentsPromptDirectory`, `ErrCacheMiss`

### `commons/utils/`
- Stateless helper functions used across layers.
- Key utilities:
  - `exceptions.go` — Custom error types implementing `error`. Always return these from use cases and repositories. Types: `ClientError (400)`, `AuthenticationError (401)`, `AuthorizationError (403)`, `NotFoundError (404)`, `InvariantError (400)`.
  - `http.go` — `SuccessResponse(c, config)` and `ErrorResponse(c, err)`. All handlers must use these. `HttpErrorHandler` is registered as Echo's global error handler.
  - `queries.go` — `GenerateQueries(db, queries, defaultLimit)` builds GORM WHERE clauses from `models.Queries`. `GenerateFilterQueries(request, options)` parses query string filters/sort from a bound request struct.
  - `agents.go` — `GetAgentPromptFileContent(fileName)` reads a prompt from `files/agents/prompts/`; `ApplyPromptPatternReplacements(template, map)` fills `{{key}}` placeholders.

### `infrastructures/configurations/`
- `Configs` struct holds `*models.ENVConfig` (`Envs`) and `*SlogLogger` (`Logger`).
- Always passed as `*configurations.Configs` to infrastructure constructors, repositories and security.
- Never instantiate configs inline — always use `configurations.NewConfigurations()`.
- Env helpers:
  - `GetEnv(key, required, default)` / `GetEnvInt(key, required, default)`
  - `GetPostgresEnvConfig(name, prefix)` — e.g. prefix `"DB_"` reads `DB_DSN`, `DB_MAX_CONN`, ...
  - `GetRedisEnvConfig(name, prefix)` — e.g. prefix `"REDIS_"` reads `REDIS_URL`, `REDIS_KEY_PREFIX`, ...

### `infrastructures/databases/`
- `DatabaseInstance` holds every database connection as an **exported** field (currently `MainDB *gorm.DB`). Repositories access it as `dbInstances.MainDB`.
- `postgres.NewPostgresInstance(configs, dbConfig, migrateModels...)` is generic — one call per database. `migrateModels` are auto-migrated only when `dbConfig.AutoMigrate` is true. Register a database's models in `databases/handler.go`.
- `redis.NewRedisInstance(configs, redisConfig)` is generic — one call per Redis. It pings on startup and returns `*RedisInstance` with:
  - `SaveCache(ctx, key, value, ttl)` — stores `value` as JSON. `ttl <= 0` uses `DefaultTTL`; zero `DefaultTTL` means no expiration.
  - `GetCache(ctx, key, &dest)` — decodes JSON into `dest`. Returns `models.ErrCacheMiss` when the key is missing; check with `errors.Is`.
  - `RemoveCache(ctx, keys...)` — deletes one or more keys; missing keys are ignored.
  - `Client` — the raw `*redis.Client` for anything else. `KeyPrefix` is **not** applied to keys used through it.
  - `Close()`
- `mongodb.NewMongoInstance(configs, mongoConfig, collectionIndexes...)` is generic — one call per database. It pings on startup (fatal on failure) and returns `*MongoInstance` with:
  - `Collection(name)` — a `*mongo.Collection` for the configured database; query with the official driver API.
  - `Client` / `Database` — the raw driver handles (transactions, other databases on the same server).
  - `CreateIndexes(ctx, collectionIndexes...)` — run automatically on startup when `AutoMigrate` is true; register each collection's `mongodb.CollectionIndexes` in the constructor call.
  - `Close(ctx)` — disconnects, waiting for in-progress operations until `ctx` is done.
  - Documents use `bson` struct tags. Not found is `mongo.ErrNoDocuments`; unique-index violations are detected with `mongo.IsDuplicateKeyError(err)`.
- Do not create a new sub-package per database. Add a config + a constructor call instead (see "Adding Another Database, Redis, Message Broker or Storage").

### `infrastructures/message_broker/`
- `MessageBroker` interface (`Publish`, `Subscribe`, `Close`) is the protocol-agnostic contract. Repositories and use cases depend on this interface, never on a concrete protocol package.
- `stomp.NewStompInstance(configs, stompConfig)` is generic — one call per connection. It connects on startup (fatal on failure) and returns `*StompInstance`:
  - `Publish(ctx, destination, payload, headers)` — payload encoded with `utils.EncodeMessagePayload`. Reconnects and retries once if the connection dropped.
  - `Subscribe(destination, handler, headers)` — consumes in a background goroutine with `client-individual` ack. Handler returning `nil` → ACK; error or panic → NACK. Resubscribes automatically after reconnect. `headers` are SUBSCRIBE headers (e.g. `prefetch-count`).
  - `Close()` — stops consumers, waits for in-flight handlers, then disconnects. Afterwards calls return `models.ErrMessageBrokerClosed`.
- Handlers receive `models.BrokerMessage`; decode JSON with `msg.Bind(&dest)`. Delivery is at-least-once — handlers must be idempotent, and should return `nil` for messages that can never succeed (malformed payloads) to avoid endless redelivery.
- go-stomp's internal logs are routed through `SlogLogger`.
- **Adding a protocol** (AMQP, Kafka, NATS, ...): create `message_broker/<protocol>/handler.go` with a `New<Protocol>Instance(configs, <Protocol>Config)` constructor implementing `MessageBroker`, add `<Protocol>Config` + `Get<Protocol>EnvConfig(name, prefix)`, and add a compile-time check `var _ MessageBroker = (*<protocol>.<Protocol>Instance)(nil)` in `message_broker/handler.go`. Reuse `models.BrokerMessage` and `utils.EncodeMessagePayload`.

### `infrastructures/storages/`
- `StorageInstance` holds `MainS3Client *s3.S3Instance` and `MainLocalStorage *localstorage.LocalStorageInstance`. Constructing it initializes both, so features that need only one should call that constructor directly.
- `s3.NewS3Instance(configs, s3Config)` is generic — one call per bucket. `S3Instance` works with any S3-compatible provider; only the config changes (`Endpoint`, `Region`, `UsePathStyle`). Do not add provider-specific packages.
- Methods: `UploadObject`, `GetObject`, `DeleteObject`, `GetPublicObjectURL`, `GetPresignedURL` (download), `GetPresignedUploadURL` (direct client upload; the client must send the signed `Content-Type`).
- All keys are prefixed with `BaseFolder`. Pass `0` as expire time to use `DefaultPresignExpire`.
- `localstorage.NewLocalStorageInstance(configs, localStorageConfig)` is generic — one call per directory. It creates `BaseDir` if missing and opens it with `os.Root`, so **every operation is confined to `BaseDir`** (path traversal and symlink escapes fail). Never build file paths yourself with `filepath.Join(baseDir, key)` — always go through the instance.
  - `SaveFile(key, reader)` / `WriteFile(key, data)` — atomic write (temp file + rename), creates parent directories, replaces existing files.
  - `GetFile(key)` (stream, caller closes) / `ReadFile(key)` — missing files return an error matching `fs.ErrNotExist`.
  - `FileExists(key)`, `ListFiles(dir)` (recursive, `""` for all), `DeleteFile(key)` (missing is not an error), `DeleteDir(key)`, `Close()`.
  - Keys are slash-separated and relative to `BaseDir`; a leading `/` is ignored.
- In Docker, `BaseDir` must be a mounted volume for files to persist. The default `storage/` is git-ignored.

### `infrastructures/langchain/`
- `NewLangChainInstance(configs)` returns `*LangChainInstance{LLM, Provider, Model}`, or `nil` when `LLM_PROVIDER` is empty — callers must handle `nil`.
- Each provider lives in `providers/<name>/handler.go` and exposes `New<Name>LLM(cfg models.LLMConfig) (llms.Model, error)`. To add a provider: add the package, a `LLMProvider` constant in `constant.go`, and a `case` in `handler.go`.
- Prompts are files in `files/agents/prompts/`, not inline strings.

### `infrastructures/repositories/`
- Repositories receive `*databases.DatabaseInstance` (and `*configurations.Configs` when needed).
- Repositories do NOT contain business logic — only data access (DB, cache, storage).
- Return custom errors from `utils/exceptions.go` on failure.

### `infrastructures/security/`
- `PasswordHashSecurity` — bcrypt hash and verify.
- `TokenManagerSecurity` — sign and verify JWT access/refresh tokens using secrets from config.

### `applications/usecases/`
- One file per domain (e.g., `authentications.go`, `system.go`).
- Struct holds repository and security dependencies injected via constructor.
- All use case methods return `error` (using `utils/exceptions.go` types) or `(value, error)`.

### `interfaces/http/api/<domain>/`
- Each domain has two files:
  - `handler.go` — struct with usecase dependency + handler methods
  - `route.go` — `RegisterRoutes(g *echo.Group)` method
- Handlers always call `utils.SuccessResponse` or `utils.ErrorResponse` — never `c.JSON` directly.
- Bind request structs using `c.Bind(&req)`, then validate with `c.Validate(&req)`.
- Routes are registered in `main.go` as: `e.Group("/domain")` → `handler.RegisterRoutes(group)`.

### `interfaces/http/middlewares/`
- **`authentications`**: Provides `VerifyClient` (checks `X-Client-Id` header — applied globally, except paths in `models.ClientVerificationSkipPaths`, e.g. health probes), `VerifyAuthentication` (checks Bearer JWT), and `VerifyAuthenticationWithServiceToken` (checks both `X-Service-Token` and Bearer JWT).
- Apply `VerifyAuthentication` or `VerifyAuthenticationWithServiceToken` to route groups that require auth, not globally.
- Authenticated user claims are stored in both places: Echo context (`c.Get(models.ContextUserClaim).(*models.AccessTokenClaims)`, handlers only) and the request `ctx` (`utils.AccessTokenClaimsFromContext(ctx)`, any layer).
- **`logger`**: `NewSlogLoggerMiddleware(configs)` logs every request through `SlogLogger` with the request ID.
- **`request_context`**: `NewRequestIDMiddleware()` (registered first) and `NewRequestTimeoutMiddleware(configs)` (`REQUEST_TIMEOUT`). Middleware order in `main.go` matters: request ID → logger → recover → CORS → body limit → timeout → client verification. CORS must run before anything that can reject a request, or browsers cannot read the error.
- **`request_limit`**: `NewBodyLimitMiddleware(configs)` rejects bodies over `REQUEST_BODY_LIMIT` with 413 (checks `Content-Length` and bytes actually read, so chunked uploads are covered too).

### `interfaces/http/api/health/`
- `/healthz` (liveness) must never check dependencies — a dependency outage would make Kubernetes restart every pod. `/readyz` runs the `health.ReadinessCheck` functions registered in `main.go` and returns 503 when any fails (details are logged, not returned).
- When wiring a new dependency (Redis, MongoDB, ...), add its `Ping` to the readiness checks: `"redis": mainRedis.Ping`. Checks must respect `ctx` so they stop when the probe times out.
- New public, unauthenticated routes must be added to `models.ClientVerificationSkipPaths`.

### Server-Sent Events (streaming)
- Use `utils.SuccessResponseSSEvent(c, utils.SuccessResponseSSEventConfig{Event, Data})` per event and `utils.ErrorResponseSSEvent(c, err)` for failures.
- `Data` as a `string` / `[]byte` is sent as-is (pre-encoded JSON is not encoded twice); any other value is JSON-encoded. Multi-line data is split into one `data:` line per line, so LLM output with newlines is safe.
- The `error` event's data is the same JSON body as `ErrorResponse`: `{code, message, error: {id, type, code, data}}`, with internal details hidden.
- Add every streaming route pattern to `models.RequestTimeoutSkipPaths`, or `REQUEST_TIMEOUT` cancels the stream (and the LLM call using the request `ctx`) when it passes.

## Context (`context.Context`)

There are two different "contexts" in this codebase:

| | `echo.Context` (`c`) | `context.Context` (`ctx`) |
|---|---|---|
| What it is | Echo's wrapper around the HTTP request/response | Go's standard cancellation + request-scoped values |
| Where it is used | **Only** in handlers and middlewares (`interfaces/http/`) | Everywhere below the handler: use cases, repositories, infrastructure |
| Get it from | Echo passes it to handlers | `ctx := c.Request().Context()` in a handler |

**Rules**

1. Handlers read `ctx := c.Request().Context()` and pass `ctx` — never `c` — to use cases.
2. Every use case, repository and infrastructure method that may do I/O takes `ctx context.Context` as its **first parameter** and passes it on to every call: `db.WithContext(ctx)`, Redis, MongoDB, S3, STOMP `Publish`, outgoing HTTP (`http.NewRequestWithContext`), LLM calls. Pure CPU helpers (JWT, bcrypt, validation) do not need it.
3. Never store a `ctx` in a struct field, and never pass `nil` — use `context.Background()` in tests and at startup.
4. Request-scoped values travel in `ctx`, not in function parameters or globals. Read them with the helpers in `commons/utils/context.go`:
   - `utils.RequestIDFromContext(ctx)`
   - `utils.AccessTokenClaimsFromContext(ctx)` / `utils.RefreshTokenClaimsFromContext(ctx)` (set by the auth middleware; `c.Get(models.ContextUserClaim)` still works in handlers)
   - New keys go in `commons/models/constant.go` as `models.ContextKey` constants, with `With…` / `…FromContext` helpers in `commons/utils/context.go`.
5. Log with `configs.Logger.InfoContext(ctx, ...)` (and `WarnContext`/`ErrorContext`/`DebugContext`) whenever a `ctx` is available — the logger adds `request_id` automatically.
6. Check for cancellation in long loops: `if err := ctx.Err(); err != nil { return err }`.
7. To keep work running after the request ends (e.g. a fire-and-forget goroutine), use `context.WithoutCancel(ctx)` — it keeps the request ID but is not cancelled with the request.

**Where contexts come from**

| Entry point | ctx | Cancelled when | Carries |
|---|---|---|---|
| HTTP request | `c.Request().Context()` | client disconnects, or `REQUEST_TIMEOUT` passes (→ 503) | request ID, token claims (after auth middleware) |
| STOMP message handler | `ctx` argument | never (handler finishes even during shutdown) | request ID = `X-Request-Id` header from the publisher, else the broker `message-id` |
| Background job | `appCtx` in `main.go` | SIGINT/SIGTERM | — |
| Startup / tests | `context.Background()` | never | — |

The request ID comes from the incoming `X-Request-Id` header (or is generated), is returned in the response header, appears on every log line, and is forwarded as an `X-Request-Id` header by STOMP `Publish` — so one ID follows a request across services and through the message broker.

**Shutdown** — on SIGINT/SIGTERM `main.go` stops accepting requests, waits up to `SHUTDOWN_TIMEOUT` for in-flight requests (their contexts are *not* cancelled by the signal), then closes resources (`dbInstances.Close()`, and any broker/Redis/Mongo instance you wire in). Add new resources to that shutdown sequence. The app logic lives in `run() int` so deferred calls still run; `main` only calls `os.Exit(run())`. A server start/runtime failure goes through the same cleanup and exits with code `1` (so Kubernetes restarts the pod); a normal shutdown exits `0`. Never call `Logger.Fatal` after startup — it skips the cleanup.

## Tests

- Standard library only (`testing`, `net/http/httptest`) — no assertion libraries. Table-driven tests with `t.Run`.
- Test files sit next to the code (`handler_test.go`). Use `package <name>_test` when the test only needs the public API, or when importing `infrastructures/configurations` from `commons/utils` would create an import cycle.
- Unit tests must not need external services. Build `*configurations.Configs` directly (`&configurations.Configs{Envs: &models.ENVConfig{...}, Logger: configurations.NewSlogLogger()}`) and use `t.TempDir()`, `t.Setenv()`.
- Code that calls `log.Fatalf` / `Logger.Fatal` is tested in a subprocess (see `infrastructures/configurations/env_test.go`).
- Run `go test ./...` before committing.

## Adding a New Domain (Step-by-Step)

1. **Model** — add request/response structs and DB model to `commons/models/<domain>.go`
2. **Repository** — create `infrastructures/repositories/<domain>.go`, implement data access via `dbInstances.MainDB.WithContext(ctx)` (GORM); every method takes `ctx context.Context` first
3. **Migration** — if the DB model needs auto-migration, pass it to `postgres.NewPostgresInstance(...)` in `infrastructures/databases/handler.go`
4. **Use case** — create `applications/usecases/<domain>.go`, inject repository, implement business logic
5. **Handler** — create `interfaces/http/api/<domain>/handler.go` + `route.go`
6. **Wire** — in `main.go`, instantiate repository → usecase → handler, then call `handler.RegisterRoutes(group)`

## Adding Another Database, Redis, Message Broker or Storage

No new package is needed — reuse the generic constructors.

**Postgres** (example: `analytics`):
1. `commons/models/configs.go` — add `AnalyticsDB PostgresConfig` to `ENVConfig` (with a comment naming its env prefix).
2. `infrastructures/configurations/env.go` — `AnalyticsDB: GetPostgresEnvConfig("analytics", "ANALYTICS_DB_"),`
3. `infrastructures/databases/handler.go` — add an `AnalyticsDB *gorm.DB` field and `postgres.NewPostgresInstance(configs, configs.Envs.AnalyticsDB, &models.Event{})`.
4. `.env_example` — add `ANALYTICS_DB_DSN`, `ANALYTICS_DB_AUTO_MIGRATE`, etc.

**MongoDB** (example: `audit`):
1. `commons/models/configs.go` — add `AuditMongo MongoConfig` to `ENVConfig`.
2. `infrastructures/configurations/env.go` — `AuditMongo: GetMongoEnvConfig("audit", "AUDIT_MONGO_"),`
3. `main.go` — `auditMongo := mongodb.NewMongoInstance(configs, configs.Envs.AuditMongo, <indexes>...)` and close it on shutdown, then inject it where needed.
4. `.env_example` — add `AUDIT_MONGO_URI`, `AUDIT_MONGO_DATABASE`, etc.

**Redis** (example: `session`):
1. `commons/models/configs.go` — add `SessionRedis RedisConfig` to `ENVConfig`.
2. `infrastructures/configurations/env.go` — `SessionRedis: GetRedisEnvConfig("session", "SESSION_REDIS_"),`
3. `main.go` — `sessionRedis := redis.NewRedisInstance(configs, configs.Envs.SessionRedis)` and `defer sessionRedis.Close()`, then inject it where needed.
4. `.env_example` — add `SESSION_REDIS_URL`, etc.

**STOMP** (example: `events`):
1. `commons/models/configs.go` — add `EventsStomp StompConfig` to `ENVConfig`.
2. `infrastructures/configurations/env.go` — `EventsStomp: GetStompEnvConfig("events", "EVENTS_STOMP_"),`
3. `main.go` (or `message_broker/handler.go`) — `eventsStomp := stomp.NewStompInstance(configs, configs.Envs.EventsStomp)` and `defer eventsStomp.Close()`.
4. `.env_example` — add `EVENTS_STOMP_ADDRESS`, etc.

**S3 bucket / local directory** (example: `media`, `cache`):
1. `commons/models/configs.go` — add `MediaS3 S3Config` or `CacheLocalStorage LocalStorageConfig` to `ENVConfig`.
2. `infrastructures/configurations/env.go` — `MediaS3: GetS3EnvConfig("media", "MEDIA_S3_"),` or `CacheLocalStorage: GetLocalStorageEnvConfig("cache", "CACHE_STORAGE_"),`
3. `infrastructures/storages/handler.go` (or `main.go`) — `s3.NewS3Instance(configs, configs.Envs.MediaS3)` or `localstorage.NewLocalStorageInstance(configs, configs.Envs.CacheLocalStorage)`.
4. `.env_example` — add `MEDIA_S3_BUCKET_NAME` / `CACHE_STORAGE_BASE_DIR`, etc.

MongoDB, Redis, the message broker and storages are not wired into `main.go` by default, so the app starts without them. Wire them in when a feature needs them.

## Response Conventions

**Success:**
```go
utils.SuccessResponse(c, utils.SuccessResponseConfig{
    Code:    http.StatusOK,
    Message: "...",
    Data:    data,
})
```

**Error (from handler):**
```go
return utils.ErrorResponse(c, err) // err must be *utils.Exceptions or error
```

**Returning errors from use cases / repositories:**
```go
return nil, utils.NewNotFoundError(errors.New("user not found"))
return nil, utils.NewClientError(fmt.Errorf("invalid input: %w", err))
```

## Caching Pattern

```go
var user models.User
err := r.mainRedis.GetCache(ctx, "user:"+id, &user)
if errors.Is(err, models.ErrCacheMiss) {
    // load from DB, then
    _ = r.mainRedis.SaveCache(ctx, "user:"+id, user, 0) // 0 = DefaultTTL
} else if err != nil {
    return nil, err
}
```
Call `RemoveCache` after any write that changes the cached data.

## Query Filtering Pattern

Use `models.BaseQueriesRequest` (or embed it) for list endpoints:

```go
type ListUsersRequest struct {
    models.BaseQueriesRequest        // provides Queries (JSON string), SortBy, Limit, Page
    Status string `query:"status"`
}
```

Parse filters with `utils.GenerateFilterQueries(request, options)`.
Build GORM query with `utils.GenerateQueries(db, queries, defaultLimit)`.

Filter operators are constants in `models/constant.go`: `OpEqual`, `OpIlike`, `OpSliceIn`, `OpBetween`, `OpOr`, etc.

## Environment Variables Reference

See `.env_example` for examples. Durations are integers in the unit shown. Empty or missing uses the default; `0` is taken literally.

**Application**

| Key | Required | Description |
|---|---|---|
| `PORT` | Yes | HTTP server port |
| `CLIENT_ID` | Yes | This service's own client ID; JWT issuer |
| `ALLOWED_CLIENT_IDS` | No | Comma-separated allowed client IDs; `*` allows all (default) |
| `ALLOWED_ORIGINS` | No | Comma-separated CORS origins; default `*` |
| `SERVICE_TOKEN` | No | Secret compared (constant-time) with `X-Service-Token` for service-to-service calls; when unset, service-token routes reject every request |
| `JWT_ACCESS_SECRET` | No | Secret for signing/verifying access tokens (HS256 only). Only needed when the service issues or verifies user tokens; when unset, tokens are never signed or accepted and a warning is logged at startup |
| `JWT_REFRESH_SECRET` | No | Secret for signing/verifying refresh tokens (HS256 only); same behaviour as `JWT_ACCESS_SECRET` when unset |
| `ACCESS_TOKEN_EXPIRATION` | No | Minutes; default 30 |
| `REFRESH_TOKEN_EXPIRATION` | No | Minutes; default 10080 (7 days) |
| `REQUEST_TIMEOUT` | No | Seconds; deadline on each request ctx (→ 503); default 30; `0` disables |
| `SHUTDOWN_TIMEOUT` | No | Seconds to wait for in-flight requests on shutdown; default 10 |
| `SERVER_READ_HEADER_TIMEOUT` | No | Seconds to receive request headers (slowloris protection); default 10; `0` disables it (not recommended) |
| `SERVER_READ_TIMEOUT` | No | Seconds to receive the whole request incl. body; disabled by default |
| `SERVER_WRITE_TIMEOUT` | No | Seconds until the response is fully written; cuts off SSE streams; disabled by default |
| `SERVER_IDLE_TIMEOUT` | No | Seconds an idle keep-alive connection stays open; disabled by default (falls back to `SERVER_READ_TIMEOUT`) |
| `REQUEST_BODY_LIMIT` | No | Max request body size such as `10M`, `512K`, `1G` (413 when exceeded); default `10M`; `0` disables it |
